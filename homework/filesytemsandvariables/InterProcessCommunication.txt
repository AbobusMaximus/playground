Inter-Process Communication (IPC)
We wan isolated processes to convey information to each other
- Used for breaking bigger tasks for efficiency
Simplest IPC form is the exit statuses of processe
- A one time opportunuty to send a single integer to the Parent process
    -This exit status indicated wether the process ran sucessfully or no 
     -exit code 0 or not 0
waitpid (process identification number)
- allows parent to wait for child process to finish
- allows the parent to read the exit status

example: 
waitpid(p1, &status, 0)
p1 = PID
&status = Pointer to an integer in which the kernel will deposit the childs exit status
0 = tells the system to wait until the child exits

Zombie processes
When a process forks a child, the child will eventually exit.
-The exit code is stored, but not in the child because that already exited
 -The kernel tracks the exit status which is there until parent calls waitpid or exits itself
The child process enters a zombie state where the process no longer exists but the kernel still tracks the PID and exit status
-These processes consume kernel resources
  -Trick is to call waitpid for each child process with -1 as the PID, which checks arbitrary childs

Limitiations of IPC via exit status
-Communicates very little info between processes
-Can only deliver the info after the program already exited, restricting listening processes

Pipe setup
A pipe provides a one directional ordered transport. 
A process can pipe to itself but its most powerful with fork()
 -Allows communication between parent and child processes

Pipes are created with the pipe() system call

File descriptors are identifiers that the kernel uses to keep track of open resources (such as files) used by user-space processes. User-space processes refer to these resources using integer file descriptor (FD) numbers; in the kernel, the FD numbers index into a FD table maintained for each process.
